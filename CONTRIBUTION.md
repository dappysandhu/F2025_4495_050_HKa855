# Contributing Guidelines

## Branch Naming Convention
- **main** → release-ready code  
- **develop** → integration branch  
- **feature/***task-name* → new features  
- **bugfix/***issue-name* → bug fixes  
- **docs/***name* → documentation updates  

Examples:
- `feature/user-authentication`
- `bugfix/login-crash`

## Commit Message Format
Follow this structure:

Types:
- **feat:** new feature  
- **fix:** bug fix  
- **docs:** documentation only  
- **style:** formatting/style  
- **refactor:** code refactor  
- **test:** adding/updating tests  
- **chore:** maintenance

## Pull Request Process
1. Create a new branch from `develop`.  
2. Commit changes with clear messages.  
3. Push branch and open a Pull Request (PR) into `develop`.  
4. Fill out the PR template checklist.  
5. At least **1 approval** required before merging.  

## Issues
- Use descriptive titles.  
- Apply relevant labels (`bug`, `enhancement`, `documentation`, etc.).  
- Reference PRs with `#issue_number`.
